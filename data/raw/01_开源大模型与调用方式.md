# 开源大语言模型与调用方式

> 课程复习资料：面向《开源软件构建技术》第七章，介绍开源大模型的基本属性和在线、离线两类调用范式。

## 1. 什么是开源大语言模型

开源大语言模型是公开模型权重、推理代码或训练相关资源，并允许开发者在相应许可证范围内使用、修改和再分发的大语言模型。开源模型的实际权利边界由许可证决定，例如 MIT、Apache-2.0 或模型社区自定义许可证。使用模型前需要核对许可证是否允许商用、是否要求保留版权声明，以及是否对模型输出或再分发附加限制。

评估一个开源模型时，通常关注以下属性：

- 模型名称与版本，例如 DeepSeek、Qwen、Llama、GLM 等系列；
- 参数规模与量化版本，参数量影响效果、显存占用和推理速度；
- 上下文窗口，决定单次可以输入多少文本；
- 支持的调用方式，包括在线 API、Ollama、Transformers 本地加载等；
- 许可证与合规要求；
- 中文能力、推理能力、代码能力以及工具调用能力。

开源不等于没有成本。在线调用需要支付 API 费用或承担网络延迟；离线部署需要准备 GPU、内存、存储和运维环境。选择方案时应该同时考虑数据安全、预算、响应时间和可维护性。

## 2. 在线调用范式

在线调用是指开发者通过网络请求访问模型服务商提供的 API，不直接在本地加载模型权重。常见做法是使用 OpenAI 兼容接口，通过 Python SDK 发送消息列表并解析响应。

在线调用的典型步骤：

1. 在模型平台注册账号并创建 API Key；
2. 将 Key 放入环境变量，不写入源代码；
3. 安装 SDK，配置模型名称和接口地址；
4. 发送系统消息与用户消息；
5. 读取响应内容，处理超时、限流和鉴权失败；
6. 记录调用成本并设置额度或重试上限。

在线调用适合以下场景：

- 快速开发验证：不必准备本地 GPU 环境；
- 需求变化快：可以较快切换模型和参数；
- 本地计算资源有限：把主要推理负载放到服务端；
- 需要实时交互：服务端通常具有稳定的吞吐能力；
- 多端应用：手机、网页和桌面端都可以调用同一个接口。

在线调用的优点是接入快、维护成本低、模型选择多。缺点是依赖网络和服务商，存在 API 费用、额度限制、数据出域和接口变更风险。对于涉及隐私的数据，应确认服务商的数据政策，必要时改用离线模型。

## 3. 离线调用范式

离线调用是把模型部署在本地或私有服务器中，在推理阶段不依赖外部模型 API。它又可以分为本地模型加载和本地化服务部署。

本地模型加载通常使用 Transformers 或 Ollama 等工具直接加载权重。例如，可以使用 Hugging Face 的 pipeline 完成文本生成，也可以直接加载 tokenizer 和因果语言模型。Ollama 则把模型下载、量化、服务启动和 API 封装整合在一起，适合个人电脑快速体验。

本地化部署通常面向团队或生产环境，需要配置模型服务、并发控制、日志、监控和硬件资源。部署时要关注显存、上下文长度、批处理大小、量化精度和推理框架。

离线调用适合以下场景：

- 数据隐私要求高：文档和问题不发送到外部服务；
- 网络环境不稳定或无法联网；
- 需要高度定制化模型；
- 对响应延迟有严格控制；
- 需要长期控制推理成本。

离线调用的优点是数据可控、可定制、长期使用时边际成本较低。缺点是需要下载模型，首次配置复杂，推理效果受本地硬件限制，小模型在复杂推理和多语言任务上可能不如在线大模型。

需要注意，“离线推理”不等于第一次安装时完全不需要网络。模型权重通常仍要从模型仓库下载，依赖包也需要提前安装。部署完成后，推理请求才可以不访问外网。

## 4. 在线与离线的选择原则

可以用以下问题做决策：

- 数据是否可以发送给第三方？如果绝对不可以，优先离线。
- 是否需要在一天内完成原型？如果时间很紧，优先在线。
- 是否已有 GPU 或足够内存？没有 GPU 时，在线或小参数模型更现实。
- 是否要求稳定复现？无论在线还是离线，都应固定模型名称、依赖版本和参数。
- 是否需要长期高频调用？高频场景要比较 API 费用与本地硬件成本。

课程项目可以采用“可切换”的设计：默认使用在线兼容接口，提供 Ollama 作为离线后端，并在没有 API Key 时启用不调用大模型的本地检索演示。这样既能展示完整 RAG 流程，又不会因为评审环境没有 Key 而无法启动。

## 5. 安全与工程实践

- API Key 只通过环境变量读取，禁止提交 `.env`；
- 设置请求超时、重试次数和最大输出长度；
- 对模型输出做必要校验，不能直接执行模型生成的代码；
- 在线模式下，在界面中提示检索片段可能发送到模型服务商；
- 离线模式下，明确模型大小和硬件要求；
- 固定依赖版本，避免框架升级导致无法复现；
- 记录模型名称、接口地址、Embedding 方案和测试日期。

## 6. 本章要点

开源大模型的选择不能只看参数规模，还要综合许可证、调用方式、硬件、数据安全和应用需求。在线调用适合快速验证和资源有限场景，离线调用适合隐私敏感和可控部署场景。对课程项目而言，最重要的是让调用链路可运行、可解释、可复现，而不是盲目追求最大的模型。
