# Agent 与 AutoGen 多智能体

> 课程复习资料：介绍智能体核心组件、ReAct 闭环、LangChain Agent 以及 AutoGen 的多智能体协作模式。

## 1. 智能体的定义

智能体（Agent）是具备自主决策、环境交互和目标达成能力的 AI 系统。它不只是生成文本，而是能够围绕目标选择下一步动作，观察行动结果，再继续规划。

智能体的核心闭环可以概括为“感知—规划—行动”：

- **感知**：读取用户目标、工具返回结果和环境状态；
- **规划**：把目标拆解为步骤，决定下一步做什么；
- **行动**：调用搜索、计算、数据库或其他工具；
- **观察**：读取工具结果，判断是否继续循环；
- **结束**：在达到目标或确认无法完成时给出最终回答。

一个典型智能体由大模型、工具集、记忆系统和代理策略组成。大模型负责推理和决策，工具扩展外部能力，记忆保存短期对话或长期知识，代理策略规定如何选择工具和终止任务。

## 2. ReAct 框架

ReAct 的核心思想是把推理（Reasoning）与行动（Acting）交替进行。模型先说明当前思考，再选择工具执行行动，读取观察结果后继续推理，直到能够回答用户。

ReAct 的典型轨迹：

1. 观察用户问题和当前状态；
2. 思考需要哪些信息；
3. 选择一个工具并构造参数；
4. 获取工具返回结果；
5. 判断结果是否足够；
6. 必要时继续调用工具；
7. 形成带依据的最终答案。

ReAct 的优点是过程透明、可调试，适合搜索问答、数据查询和多步骤任务。缺点是会增加调用次数和延迟，也可能出现参数格式错误、重复调用工具或陷入循环等问题。因此需要设置最大步骤数、工具白名单、超时和异常恢复策略。

## 3. 使用 LangChain 构建单 Agent

使用 LangChain 构建单 Agent 通常包含三个阶段：

1. **工具定义**：把搜索、计算、数据库或业务 API 封装成模型可调用的工具，并提供清晰的名称、说明和参数模式；
2. **智能体初始化**：把聊天模型、工具列表和代理策略组合起来；
3. **任务执行**：传入用户目标，让 Agent 自主选择工具并返回结果。

工具描述会直接影响模型是否能正确选择工具。描述应该说明工具能做什么、不能做什么、参数含义和返回格式。对于高风险操作，应增加人工确认，不能把删除文件、付款或执行任意代码直接暴露给模型。

## 4. AutoGen 多智能体

AutoGen 是一个允许多个智能体通过对话协作完成任务的框架。开发者可以创建不同角色的 Agent，为它们设置系统消息、模型配置和工具，然后按照某种拓扑组织对话。

多智能体的价值在于角色分工。例如，一个 Agent 负责检索资料，一个负责分析数据，一个负责撰写报告，最后一个负责质量检查。相比让单个 Agent 同时完成所有任务，分工可以降低提示词复杂度，并让每个角色聚焦于特定职责。

但多智能体并不总是优于单智能体。角色越多，消息传递、状态同步、成本和失败恢复就越复杂。只有任务确实需要多种能力或明确分工时，才值得使用多智能体。

## 5. AutoGen 的典型协作模式

AutoGen 常见的协作模式包括：

- **对等式（Peer-to-Peer）**：多个 Agent 地位平等，按需交互，适合开放式讨论和互相补充；
- **轮询式（Round-Robin）**：Agent 按固定顺序轮流发言或执行任务，适合稳定的流水线协作；
- **层级式（Hierarchical）**：管理者 Agent 分配任务给执行 Agent，适合“规划—执行—汇总”的复杂流程。

选择模式时应考虑任务是否需要人类参与、是否需要严格顺序、是否需要管理者仲裁，以及失败时如何终止对话。

## 6. 多智能体的工程风险

- 对话可能无限循环，必须设置最大轮数；
- Agent 之间可能重复工作，需要明确职责和终止条件；
- 工具调用可能失败，需要处理重试和错误信息；
- 多轮消息会增加 Token 成本；
- 多个 Agent 可能互相强化错误，需要加入验证角色或人工审核；
- 执行代码或修改文件属于高风险动作，应在沙箱中运行。

在生产环境中，应记录每个 Agent 的输入、输出、工具调用和终止原因，便于审计和优化。

## 7. 单 Agent 与多 Agent 如何选择

如果任务只有一条明确流程，优先使用普通 Chain 或单 Agent。只有当任务需要明显不同的专业角色、需要并行探索多个方案，或者需要管理者统一协调时，再考虑多 Agent。

课程项目的评价重点不是 Agent 数量，而是：

- 工具是否真实可用；
- 调用轨迹是否可解释；
- 是否有错误处理和终止条件；
- 最终结果是否经过验证；
- README 是否说明架构和限制。

## 8. 本章要点

智能体通过“大模型 + 规划 + 记忆 + 工具”突破单轮文本生成，但也带来成本、延迟和安全风险。ReAct 提供了推理与行动交替的基本范式，LangChain 适合构建单 Agent，AutoGen 适合实现角色协作。选择架构时应从任务需求出发，不要为了使用多智能体而增加不必要的复杂度。
