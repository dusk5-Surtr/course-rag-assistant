# 第七章智能应用开发作业说明

> 课程复习资料：整理第七章作业的交付要求、推荐技术路线和提交前检查项。

## 1. 作业目标

第七章作业要求基于 LangChain 框架、在线大模型或者离线大模型，开发一款智能应用。作业需要提交智能应用的 README 文档说明，并附带智能应用的开源仓库链接。

作业的重点不是堆叠最多组件，而是完成一个可运行、可解释、可复现的应用闭环。推荐选择课程资料知识库问答、长文档总结、代码理解或智能体工具调用等方向。

## 2. 推荐交付内容

一个合格的项目至少应包含：

- 可运行的源代码和明确的应用入口；
- `requirements.txt` 等依赖文件；
- `.env.example`，但不得提交真实 `.env`；
- 至少一份可公开的示例资料；
- 完整 `README.md`；
- 开源许可证文件；
- 配置说明、启动命令和使用示例；
- 5 至 10 条测试问题及结果记录；
- 在线或离线模型的配置说明；
- 已知限制和安全注意事项。

## 3. RAG 问答助手的推荐链路

课程资料 RAG 问答助手可以采用以下技术路线：

1. 使用文档加载器读取 PDF、Markdown 或 TXT；
2. 使用文本分割器生成带元数据的片段；
3. 使用 Embedding 模型生成向量并保存到向量库；
4. 用户提问时检索最相关的若干片段；
5. 使用 LangChain 提示词模板组合问题与上下文；
6. 调用在线大模型或 Ollama 离线模型生成答案；
7. 在界面中展示答案、来源文件、页码或片段编号；
8. 对资料不足的问题明确拒答；
9. 记录测试问题和评测结果。

在线模型适合快速验证，离线模型适合隐私敏感场景。没有 API Key 时，应提供明确标注的本地演示模式，保证评审能够启动界面并检查检索、引用和异常处理，而不是把演示模式宣称为真实大模型输出。

## 4. README 必须说明的内容

README 应回答以下问题：

1. 项目解决什么问题，目标用户是谁；
2. 应用有哪些已实现和未实现功能；
3. 使用了什么模型、LangChain 组件、Embedding 和向量库；
4. 系统架构和数据流是什么；
5. 如何安装依赖、配置环境变量、准备资料和启动应用；
6. 在线与离线模式如何切换；
7. 示例资料从哪里来，是否可以公开；
8. 如何运行测试，评测结果如何；
9. 项目有哪些已知限制；
10. 项目采用什么许可证，开源仓库在哪里。

README 中的命令必须经过真实运行验证。不要写不存在的测试、功能和截图。

## 5. 仓库检查

提交前应确认：

- 仓库已设为公开，链接在退出登录状态下也能访问；
- 默认分支根目录可以看到 `README.md`；
- 代码、依赖、示例数据和许可证齐全；
- `.env`、API Key、个人隐私和受限版权资料没有进入 Git 历史；
- 向量库缓存、虚拟环境和日志没有提交；
- 提交历史能体现开发过程；
- 在干净目录克隆后可按 README 启动。

## 6. 提交文案建议

作业平台文本提交可以包括：

- 项目名称与一句话简介；
- 技术路线，例如 LangChain + 在线模型/离线模型 + Embedding + 向量库 + Streamlit；
- 核心功能与使用流程；
- 公开仓库链接；
- README 附件说明；
- 已完成的自测情况和已知限制。

附加文件上传 README.md；如果平台不能预览 Markdown，可以同时上传 README.pdf。提交前应点开仓库链接和附件各检查一次。

## 7. 自检重点

- 应用能否从零启动；
- 是否有真实检索和真实模型调用路径；
- 答案是否带来源；
- 资料不足时是否拒答；
- 是否有 API Key 泄露风险；
- 是否有可复现的测试记录；
- README 是否让陌生人能完成部署。

完成以上项目，比单纯增加页面数量或模型数量更能体现工程质量。
