# RAG 检索增强生成原理与实现

> 课程复习资料：解释 RAG 的索引、检索和生成流程，以及来源引用、拒答和评测方法。

## 1. RAG 要解决的问题

大语言模型的知识来自训练数据，存在两个明显限制。第一，训练数据有时间截止点，模型无法自动知道最新资料。第二，模型可能生成看似合理但缺乏事实依据的内容，这种现象通常称为幻觉。

检索增强生成（Retrieval-Augmented Generation，RAG）的做法是：先从外部知识库检索与问题相关的片段，再把片段和问题一起交给大模型生成答案。模型不直接依赖记忆，而是根据检索到的事实组织语言。

RAG 的主要价值包括：

- 提高知识时效性：更新知识库即可，不必重新训练模型；
- 降低幻觉风险：答案可以追溯到原始资料；
- 降低领域适配成本：无需微调即可接入垂直知识；
- 增强可解释性：向用户展示来源文件和片段；
- 保护部分私有知识：知识留在自己的存储中，只把必要片段发送给模型。

RAG 并不能完全消除幻觉。检索噪声、文档质量、切分策略、提示词和模型能力都会影响最终效果。

## 2. RAG 的三大阶段

一个典型的 RAG 系统包含索引、检索和生成三个阶段。

### 2.1 索引阶段

索引阶段在离线或后台完成，包括以下步骤：

1. **加载**：使用文档加载器读取 PDF、Markdown、TXT 或数据库内容；
2. **拆分**：把长文档切成较小的文本块，并保留文件名、页码、章节等元数据；
3. **向量化**：使用 Embedding 模型把每个文本块转换为向量；
4. **存储**：把文本、向量和元数据写入向量库或可检索的索引结构。

索引阶段的目标是让内容“可被找到”，并不直接回答用户问题。索引质量差，后续生成能力再强也难以补救。

### 2.2 检索阶段

用户提出问题后，系统先把问题转换为查询向量，再从向量库中找出最相似的若干文本块。这个过程通常用 top-k 表示，例如返回最相关的 4 到 6 个片段。

为了提高效果，可以加入：

- 关键词检索与向量检索的混合检索；
- 元数据过滤，例如只检索指定课程或文件；
- 重排序（Rerank），用专门模型重新排列候选片段；
- 相似度阈值，过滤明显不相关的结果；
- 查询改写，把口语问题转换为更适合检索的表达。

检索结果不是越多越好。过多片段会增加上下文长度、成本和噪声，过少则可能遗漏答案。

### 2.3 生成阶段

生成阶段把用户问题、检索片段和回答约束组合为提示词，再交给大模型。提示词应要求模型：

- 只依据提供的资料回答；
- 对关键结论标注来源；
- 资料不足时明确说明；
- 不补充未经资料支持的事实；
- 使用清晰、简洁的结构。

最终答案应同时返回来源片段，让用户可以核验。仅仅返回一段自然语言答案，无法证明内容真的来自知识库。

## 3. 文本切分策略

文本块的 `chunk_size` 和 `chunk_overlap` 是 RAG 的关键参数。块太大时，检索会混入无关内容，也会占用模型上下文；块太小时，语义可能被切断。

课程资料可以从以下范围开始试验：

- 中文资料 `chunk_size`：500 到 1000 个字符；
- `chunk_overlap`：100 到 200 个字符；
- `top_k`：先从 3 到 5 个片段开始；
- 优先按标题、段落、句子切分，而不是直接按固定字符硬切。

切分后要检查每个块是否包含完整语义，并保留 `file_name`、`page`、`chunk_index` 和 `citation` 等元数据。引用标识应该稳定，不能因为页面刷新而变化。

## 4. 降低幻觉的方法

RAG 降低幻觉的关键不是一句“不要编造”，而是把检索、提示词和界面一起设计：

1. 使用质量可靠、来源明确的资料；
2. 对问题执行相关性过滤，不把无关片段强行塞给模型；
3. 在系统提示词中规定“只依据上下文”；
4. 要求引用具体来源，促使模型核对上下文；
5. 让模型在资料不足时拒答；
6. 在界面中展示来源，允许人工核验；
7. 建立固定问题集，定期评估检索命中率和回答质量。

对于知识库外问题，理想的输出是“知识库中未找到足够依据”，而不是根据常识给出一个看似合理的答案。

## 5. RAG 评测方法

课程项目至少可以建立 5 到 10 条问题，覆盖：

- 事实查询：答案是否能在单个片段中找到；
- 跨片段综合：是否需要组合多个来源；
- 边界问题：资料不足时是否拒答；
- 噪声问题：检索是否被无关内容干扰；
- 异常场景：空文档、损坏文件或无 API Key 时是否友好提示。

可以记录以下指标：

- **答案可用性**：人工判断答案是否解决了问题；
- **来源正确率**：引用片段是否真的支持答案；
- **拒答正确率**：知识库外问题是否被正确拒绝；
- **检索命中率**：正确片段是否出现在 top-k 中；
- **平均响应时间**：从提交问题到显示答案的耗时。

评测不一定要使用复杂工具，固定的问题表和可复现的结果记录就足以展示工程意识。

## 6. 常见问题与排查顺序

当回答不准确时，建议按以下顺序排查：

1. 文档是否成功解析，扫描版 PDF 是否有文本层；
2. 检索出的片段是否与问题相关；
3. 切分是否切断了关键语义；
4. 提示词是否明确要求依据资料回答；
5. `top_k` 是否过小或过大；
6. 模型是否被要求输出引用；
7. 知识库是否真的覆盖该问题。

不要一上来就更换更大的模型。很多 RAG 失败来自检索错误或文档解析错误，与模型参数规模无关。

## 7. 本章要点

RAG 通过“索引、检索、生成”把外部知识接入大模型。一个可交付的 RAG 应用不仅要能回答问题，还应展示来源、处理资料不足、记录参数并提供可复现的测试。对于课程作业，稳定的闭环、清晰的引用和真实的评测记录，比堆叠复杂组件更重要。
